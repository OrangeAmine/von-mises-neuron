## Pilot terminal-monitor error

The pilot completed its full six-unit matrix (12 peak fits and two full proxy
fits, each with a separately retrained sensor-only readout) in **32.247 seconds**.
Every unit had already saved a complete receipt, metrics, arrays and fitted state.
The runner then raised at the end-of-stage process check because resident Python
PID 7228 advanced from **25.703125 to 25.718750 CPU seconds**: one 15.625 ms tick.
Its five-second preflight sample was unchanged. Earlier observations minutes
apart were also unchanged, with occasional later CPU ticks.

This observation establishes some CPU activity by a CUDA-resident process; it
does not identify competing GPU training. CPU counters and start/end snapshots
cannot exclude GPU-only activity or a process that starts and exits between
snapshots. The study therefore cannot claim isolated-hardware timing.

The protocol requires checking before timed runs and recording observed
contention. The implementation had added an overstrict terminal rejection for
any CPU tick. A narrow operational correction retains the preflight check and
the terminal observations but stops treating this terminal observation as a
failed scientific fit. No data, model, optimizer, seed, checkpoint rule,
comparison, threshold, or compute ceiling changes. No pilot fit is repeated and
no extra function is generated. No scientific metric was inspected to choose
this correction; only completion, process counters and elapsed time were read.

The original error receipt, all per-unit artifacts and original source manifest
remain intact. The original runner bytes are archived with SHA256
`ea4879ebc35941669320931bda1361f1fe316c0ee747cf2ffee778205714678d`.
A separate source amendment identifies the corrected runner and binds the
archived original. A separate completion adjudication verifies the entire saved
matrix, retains the monitor error, and charges finalization overhead. Reserved
access must bind both records and both measured precursor projections.

This is a disclosed post-pilot operational amendment, not a claim of entirely
unchanged orchestration or a clean original pilot exit. Scientific sources and
all numerical rules remain prospective for development and evaluation. Possible
background load makes the measured cap check conservative; these timings are
feasibility measurements, not a speed comparison.
